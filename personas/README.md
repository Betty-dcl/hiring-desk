# Synthetic candidates

Five invented people. The names, employers, schools and dates are fictional,
and no part of any file here describes a real person.

They exist because a screener that has only ever been pointed at good
applications has not been tested. Each one probes a specific way this system
could fail, and each one has an expectation attached — recorded in
`expectations.toml`, written before the screener ever ran, so that a
disagreement between expectation and result is a finding rather than a
rationalisation.

| persona | what it probes |
|---|---|
| `mara_velichko` | a keyword stuffer: says every phrase the posting uses, shows nothing |
| `tomas_renner` | an overclaimer: enormous scope, no specifics, no verifiable outcome |
| `ines_abadi` | genuinely strong, understated: does the screener reward substance or volume |
| `paul_okonkwo` | adjacent and strong: excellent, in a domain the posting did not ask for |
| `sylvia_hartmann` | non-linear path with gaps: is UNKNOWN used, or is a gap penalised |

The reviewer names that appear in the demo pipeline records — `iris_vogel`,
`noam_castel` — are invented on the same basis. Nobody named in any record in
this repository is a real person, and no record describes a real hiring
process.

The `*_note.md` files are the "few lines on what you're great at and what
you'd want to own" that the open-door page asks for, written to match each
CV: Inès's is concrete and points at the tool she built, Mara's recites the
posting, Paul's is an engineer's answer to a business role. The links in them
use the reserved `.example` domain, so they point at nobody.
